# eit_dem — SOHO/EIT 4채널로 기준 DEM 보정하기

이 코드는 관측값만으로 새로운 DEM을 처음부터 푸는 일반적인 역산 코드가 아니다. 미리 준비한
기준 DEM과 채널별 예상 밝기를 놓고, 실제 관측과의 비율로 기준 DEM을 온도별로 보정한다.

## 먼저 읽기

171, 195, 284, 304 Å 채널은 서로 다른 온도 성분이 섞여 있다. 코드는 비교적 단순한 채널부터
차례로 성분을 분리하고, `관측 밝기 / 예상 밝기`의 로그값을 보정계수로 만든다. 몇 개 온도에서
구한 보정계수를 직선이나 이차식으로 이어 전체 DEM 맵을 만든다.

이 결과에는 코드가 미리 정한 경험적 가정이 많이 들어간다.

- 26개 온도 구간 중 처음 6개는 관측으로 얻은 값이 아니라 가정한 연속광 부분이다.
- `logT=6.4`와 `6.5` 부근에는 값이 지나치게 커지지 않도록 제한이 걸려 있다.
- 보정 배율에는 10⁴ 상한이 있고, 매우 어두운 픽셀에는 바닥값이 적용된다.
- χ²를 내놓지 않으므로 적합이 좋은지 별도로 확인해야 한다.

25개 비교 항목과 회귀 테스트 6개를 통과했다. CHIANTI로 예상 밝기를 만드는 `eit_line_map`
부분은 옮기지 않았고, 그 결과값을 외부 입력으로 받는다.

- IDL 원본: `idl/`
- Python 변환본: `python/`

## 1. 방법 요약 — 기준 DEM 보정

SOHO/EIT는 171, 195, 284, 304 Å의 네 채널을 사용합니다. 이 코드는 일반적인 matrix
inversion 대신 기준 DEM을 채널 비율로 보정합니다.

**행렬을 풀어 DEM을 구하는 게 아닙니다.**

기준 DEM을 놓고 CHIANTI로 **예상 DN을 미리 계산**한 뒤, **관측 DN / 예상 DN의 로그 비율**을 온도별 **보정계수**로 삼습니다. 그 보정계수를 다항식으로 적합해 온도축 전체로 펼치면 DEM 맵이 됩니다.

```
기준 DEM  ──CHIANTI──▶  예상 DN
                            │
관측 DN ────────────────────┤
                            ▼
                  kcorr = log₁₀(관측 / 예상)     ← 채널별 보정계수
                            │
                     다항식 적합 (e_fit2)
                            ▼
                  온도별 보정 → DEM 맵
```

|  | 역산 계열 | eit_dem |
|---|---|---|
| 미지수를 푸는 방식 | 연립방정식 / 최적화 | 비율 계산 + 다항식 적합 |
| 정규화 | 페널티 / 기저 축소 / L1 | 다항식 차수(1차·2차) + 경험적 값 제한 |
| 사전지식 | 매끄러움 | 기준 DEM 곡선 자체 |
| χ² | 핵심 판정 기준 | 없음 |

따라서 결과는 **기준 DEM이 실제 분포와 얼마나 가까운지**에 크게 의존합니다. `kcorr`가
`log10(관측/예상)`이므로 절댓값이 0에 가까울수록 기준 DEM과 관측의 차이가 작다는 뜻입니다.

## 2. e_interp / e_fit2 — 두 개의 도구 함수

### e_interp — 두 점 사이 선형 보간 18–21

```
def e_interp(img1, img2, t1, t2, t3):
    slope = (img2 - img1) / (t2 - t1)
    return slope * (t3 - t1) + img1
```

온도 `t1`, `t2` 에서의 두 이미지를 받아 중간 온도 `t3`의 값을 추정합니다. **이미지 전체에 대해 한 번에** 동작합니다(numpy 브로드캐스팅).

### e_fit2 — 다항식 계수를 행렬 역산으로 24–42

`x`의 개수에 따라 세 가지 모드가 있는데, 실제로 쓰이는 것은 `n = 5` 입니다.

```
mat = [[x0,  1,   0,    0,  0],      ┐
       [x1,  1,   0,    0,  0],      ┘ 앞 2개 점 → 1차식
       [ 0,  0,  x2²,  x2,  1],      ┐
       [ 0,  0,  x3²,  x3,  1],      │ 뒤 3개 점 → 2차식
       [ 0,  0,  x4²,  x4,  1]]      ┘
```

**블록 대각 행렬입니다.** 왼쪽 위 2×2와 오른쪽 아래 3×3이 서로 **완전히 분리**돼 있습니다. 즉 하나의 5차 다항식이 아니라, **저온 구간은 직선 · 고온 구간은 포물선**으로 **따로 적합**하는 조각별(piecewise) 모델입니다.

결과 `coefs` 5개 = `[a, b, c, d, e]` → 저온: `a·t + b`, 고온: `c·t² + d·t + e`

```
inv = np.linalg.inv(mat)
return (inv @ y.T).T            # IDL invert(mat) ## y
```

> **IDL 문법 주의.** `#`과 `##`는 contraction axis가 서로 다릅니다. 여기서는 `##`이므로
> `(inv @ y.T).T`로 옮겼습니다. IDL 행렬 연산을 NumPy로 옮길 때 두 연산자를 구분해야 합니다.

`y`는 `(npix, nfit)` 형태로 **모든 픽셀을 한 번에** 처리합니다. 행렬 역산은 픽셀과 무관하므로 **한 번만** 계산하면 됩니다.

## 3. eit_kcorr_iter — 섞인 채널을 풀어내기

이 함수가 EIT DEM의 물리적 핵심입니다. 문제는 **284와 304 채널이 여러 온도의 기여가 섞여 있다**는 점입니다.

### 깨끗한 두 채널 먼저 60–62

```
kcorr171 = log10( max( max(e171, 0.1) / max(dn_pred_171, 0.1), 1e-5 ) )
kcorr195 = log10( max( max(e195, 0.1) / max(dn_pred_195, 0.1), 1e-5 ) )
```

171과 195는 단일 온도 성분이 지배적이라 **바로 로그 비율**을 취합니다.

`max(..., 0.1)` ( `lowsig` )과 `max(..., 1e-5)`는 **어두운 픽셀에서 0으로 나누기와** `log(0)` **을 막는 안전장치**입니다. 세 겹으로 걸려 있습니다.

### 284 채널 — cool 성분 빼내기 64–66

```
k284_cool = e_interp(kcorr304, kcorr171, x[0], x[1], x[4])   # ① 보간으로 추정
cool_284  = (10.0 ** k284_cool) * cool_284                    # ② 보정 적용
kcorr284  = log10( max( (max(e284,0.1) - cool_284) / max(hot_284,1e-5), 1e-5 ) )  # ③
```

1. 284의 **저온 기여분**에 대한 보정계수를, 이미 구한 `kcorr304`와 `kcorr171` 사이를 보간해 추정합니다

2. 그 보정을 예측 cool 성분에 곱해 **실제 cool 기여량**을 얻습니다

3. 관측값에서 **빼내고**, 남은 것을 hot 성분에 대한 보정으로 해석합니다

### 304 채널 — warm과 hot을 순차로 68–73

```
k304_warm = e_interp(kcorr171, kcorr195, x[1], x[2], x[5])   # warm 보정 추정
warm_304  = (10 ** k304_warm) * warm_304
k304_hot  = e_interp(kcorr195, kcorr284, x[2], x[3], x[6])   # hot 보정 추정 (방금 구한 kcorr284 사
용)
hot_304   = (10 ** k304_hot) * hot_304
hot_304   = hot_304 + warm_304                          # 둘을 합쳐
kcorr304  = log10( max( (max(e304,0.1) - hot_304) / cool_304, 1e-5 ) )   # 관측에서 제거
```

**순서가 중요합니다.** 171·195 → 284 → 304 순으로 **앞에서 구한 보정계수를 뒤에서 재사용**합니다. 특히 304의 hot 보정은 **방금 계산한** `kcorr284`를 씁니다. 그래서 함수 이름에 `iter` (반복)가 붙어 있습니다 — 이 전체를 여러 번 돌리면 보정계수가 서로를 갱신하며 수렴해갑니다.

**변환 범위 참고:** 여기 옮긴 것은 `/iter` 분기입니다. non- `/iter` 분기는 내부에서 `eit_line_map` (CHIANTI forward model)을 직접 호출하므로 **범위 밖**이고, 대신 그 출력인 `dn_maps`를 외부에서 받습니다.

## 4. dem_map_expand — 계수를 DEM 맵으로

### 온도별 보정값 계산 88–100

```
for i in range(nt):
    this_t = temp[i]
    if this_t <= x1:
        kcorr_t = coefs[:,:,0]*this_t + coefs[:,:,1]                        # ① 저온: 1차
    else:
        kcorr_t = coefs[:,:,2]*this_t**2 + coefs[:,:,3]*this_t + coefs[:,:,4]  #    고온: 2차
    if this_t == np.float32(6.3):  k63 = kcorr_t                            # ② 기준값 저장
    if this_t == np.float32(6.4):  kcorr_t = min(max(kcorr_t, k63-3), k63+0.6)   # ③ 클램핑
    if this_t == np.float32(6.5):  kcorr_t = min(max(kcorr_t, k63-6), k63+1.0)
    dem_m[:,:,i] = np.maximum(dem[i] + np.minimum(kcorr_t, 4), 0)           # ④ 적용
```

**① 조각별 적합 평가**

`e_fit2`가 만든 5개 계수를 **온도에 따라 다른 식으로** 씁니다. 경계는 `x[1]` 입니다.

**③ 고온 값 제한 — 경험적 안전장치**

`logT = 6.4`와 `6.5`에서 보정값을 `6.3` **에서의 값(** `k63` **) 기준으로 강제 제한**합니다.

2차 다항식은 고온 끝에서 **급격히 발산**할 수 있는데, EIT 채널들은 그 온도대에 감도가 거의 없어 **데이터가 뒷받침하지 못하는 외삽**이 됩니다. 위쪽은 좁게(+0.6, +1.0), 아래쪽은 넓게(−3, −6) 잡은 비대칭 범위도 **"고온 DEM을 과대추정하지 말라"**는 물리적 판단을 반영합니다.

이론적 근거가 아니라 **경험적으로 정해진 상수**입니다.

**④ 기준 DEM에 보정 적용**

```
dem_m = max( dem[i] + min(kcorr_t, 4), 0 )
```

`dem`은 기준 DEM의 **로그값**이므로 보정을 **더하기**로 적용합니다(로그 공간에서 덧셈 = 실수 공간에서 곱셈). `min(kcorr_t, 4)`는 보정 배율을 **10⁴배로 상한**을 두고, 바깥 `max(..., 0)`은 음수 로그 DEM을 막습니다.

### 저온 continuum 이어붙이기 102–108

```
dem_scale = dem_m[:,:,0] / 21.897
dem2      = [26.391, 25.383, 24.469, 23.654, 22.946, 22.357]   # 고정 모양
temp2     = np.arange(26)*0.1 + 4.0                             # logT 4.0 ~ 6.5
dem_map[:,:,6:] = dem_m                        # 계산된 부분
for i in range(6):
    dem_map[:,:,i] = dem2[i] * dem_scale       # 저온 6칸은 고정 모양을 스케일링
```

EIT 4채널은 `logT 4.0~4.5` 영역에 **감도가 없습니다.** 그래서 이 구간은 계산하지 않고, **미리 정해진** **continuum 모양(** `dem2` **)**을 가져와 계산된 부분의 첫 값에 맞춰 스케일링합니다.

**즉 최종 DEM 맵의 앞 6칸(전체 26칸 중)은 관측에서 나온 값이 아니라 가정입니다.** 사용 시 반드시 인지해야 할 부분입니다.

## 5. 변환에서 조심한 것 — float32 동등 비교

```
if this_t == np.float32(6.3):  ...
if this_t == np.float32(6.4):  ...
if this_t == np.float32(6.5):  ...
```

> **⚠** `np.float32()` **를 벗기면 코드가 조용히 망가집니다.**

`temp`는 IDL `fltarr`에서 온 **float32** 배열입니다. Python에서 그냥 `this_t == 6.3` 이라고 쓰면 오른쪽이 **float64** `6.3`이 되는데, `float32(6.3)`과 `float64(6.3)`은 **비트가 다른 서로 다른 수**입니다. 비교가 항상 `False`가 되어 **값 제한 블록 전체가 실행되지 않고**, 그래도 에러는 나지 않습니다.

부동소수점 동등 비교는 일반적으로 피해야 할 패턴이지만, 여기서는 **IDL 원본의 동작을 재현해야 하므로** 양쪽 타입을 정확히 맞추는 것이 정답입니다.

### 기타 IDL ↔ Python

| IDL | Python |
|---|---|
| invert(mat) ## y | (np.linalg.inv(mat) @ y.T).T |
| 원소별 >  / < | np.maximum  / np.minimum |
| fltarr  (float32) | dem_map · kcorr 는 float32, 내부 연산은 float64 |
| temp eq 6.3 | this_t == np.float32(6.3) |

## 6. 변환 및 검증 범위

### 결과

| 항목 | 값 |
|---|---|
| 세트 | set1 — 결정론적 합성 입력 |
| 판정 | 모두 통과 — 25 통과 / 0 차이 허용 / 0 실패 |
| e_fit2 | double 1e-10 통과 (순수 행렬 산술) |
| kcorr  · dem_map | float32 1e-5 통과 |
| 회귀 테스트 | 6/6 |

**중간값을 저장한 방식이 다릅니다.** 다른 패키지는 IDL 루틴에 중간값를 심은 중간값 저장용 코드을 만들었지만, 이 패키지는 **드라이버 레벨에서 중간값를 저장**했습니다. 즉 `e_fit2` · `eit_kcorr` 원본을 **전혀 수정하지 않고** 호출했으므로, 중간값 저장 전후 결과이 **자동으로 보장**됩니다.

### 옮기지 않은 부분

| 제외 항목 | 사유 |
|---|---|
| eit_line_map | CHIANTI 기반 EIT DN forward model. 응답 입력 준비 코드이므로 출력( dn_maps )을 외부 입력 — AIA solver들의 aia_get_response  외부 입력과 동일 패턴 |
| eit_prep | 이미지 I/O |
| 1024×1024 파이프라인, ptr/struct 기계 | SSW 입력 준비 코드 |
| eit_kcorr  non- /iter  분기 | 내부에서 eit_line_map 을 직접 호출 → 범위 밖 |

정리하면 계수 적합, 보정 계산, DEM 확장은 Python으로 옮겨 확인했습니다. CHIANTI 응답을 써서
채널 밝기를 계산하는 부분만 외부 입력으로 남겼습니다.

### 사용 시 주의사항

**결과가 기준 DEM에 의존합니다.** 보정계수가 클수록 신뢰도가 떨어집니다

**최종 DEM 맵 26칸 중 앞 6칸(** `logT 4.0~4.5` **)은 가정된 continuum**입니다 — 관측 정보가 아닙니다

`logT 6.4` · `6.5`의 값은 **경험적 값 제한**이 걸려 있습니다. 원래 적합값이 아닐 수 있습니다

보정 배율에는 **10⁴의 상한**이 있습니다(`min(kcorr_t, 4)`).

`lowsig = 0.1`의 하한 때문에 매우 어두운 픽셀에서는 보정계수가 하한값에 의해 결정될 수 있습니다.

χ²를 반환하지 않으므로 적합도를 별도로 확인해야 합니다.

**기록의 근거.** 코드 설명은 `idl/eit_dem_tool.pro`와 `python/eit_dem.py`를 바탕으로 작성했다.
보정 한계값의 의미는 코드 동작을 풀어 설명한 것이며, 별도의 방법 논문에서 확인한 내용은 아니다.
검증 수치는 변환 작업 당시의 비교 보고서를 따른다.

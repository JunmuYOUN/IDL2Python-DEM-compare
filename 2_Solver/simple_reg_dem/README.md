# simple_reg_dem — 빠르고 단순한 정규화 DEM

이 코드는 여러 채널의 밝기에서 온도별 DEM을 구한다. 관측 채널 수보다 온도 구간 수가 훨씬
많아 inversion이 ill-posed하므로, 관측값을 설명하면서 불필요한 진동을 억제한 해를 찾는다.

## 먼저 읽기

핵심은 세 가지다.

1. DEM 자체가 아니라 `log(DEM)`을 계산해 결과가 음수가 되지 않게 한다.
2. 이웃한 온도 구간의 DEM이 너무 급하게 달라지면 벌점을 준다.
3. χ²를 무조건 가장 작게 만들지 않고, 입력 오차와 맞는 수준인 χ²≈1을 목표로 한다.

입력은 관측값, 관측 오차, 온도 응답함수다. 출력은 DEM 맵과 채널당 평균 χ²다. DEM 오차나
온도 해상도는 따로 내놓지 않는다. 각 픽셀을 독립적으로 계산하므로 빠르지만 이웃 픽셀끼리
매끈하게 이어진다는 보장은 없다. 특히 χ² 목표가 입력 오차를 믿고 정해지므로 `errors`의 품질이
결과에 직접 영향을 준다.

합성 5×5 자료에서 24개 항목이 맞았고 float32 반올림에 따른 작은 차이 2개를 허용했다. 실제
크기의 100×100 및 512×832 자료와 회귀 테스트 7개도 통과했다.

## 1. 이 코드가 푸는 문제

태양 코로나를 여러 파장으로 찍은 관측에서 **온도별 플라즈마 양 분포**(DEM)를 복원하는 것이 목표입니다.

```
관측된 밝기(채널 c) = ∫ K_c(T) × DEM(T) dT
```

`K_c(T)` — 온도응답함수. "온도 T의 플라즈마가 채널 c에 얼마나 밝게 보이나". **알고 있음**

`DEM(T)` — 온도 T의 플라즈마가 얼마나 있나. **구하려는 것**

### 왜 어려운가 — ill-posed

이 프로젝트 설정 기준으로 **관측은 6개(AIA 6채널), 미지수는 41개(온도격자)**입니다. 6개 방정식으로 41개를 푸는 셈이라 답이 무한히 많습니다.

게다가 응답함수 `K_c(T)` 들이 온도축에서 넓게 겹칩니다. 이 때문에 잡음이 조금만 있어도:

해가 톱니처럼 심하게 진동하고

**음수 DEM**이 튀어나옵니다 (물리적으로 불가능 — 플라즈마 양이 음수일 수 없음)

**모든 DEM solver는 결국 "이 ill-posed 문제를 어떻게 길들이냐"에 대한 서로 다른 대답입니다.** simple_reg_dem은 그중 가장 단순한 축에 속합니다 — 파일 하나, 주석 포함 86줄, 외부 라이브러리 의존 0.

### 이 문서 내내 쓰는 숫자

```
채널       6개  : AIA 94, 131, 171, 193, 211, 335 Å
온도격자  41개  : logT = 5.5, 5.55, 5.60, … , 7.5   (간격 0.05)
이미지          : nx × ny 픽셀 (실제 검증에서는 512 × 832 = 42.6만 픽셀)
```

## 2. 핵심 아이디어 세 가지

### ① 로그 공간에서 푼다 → 음수가 안 나온다

DEM을 직접 구하지 않고 `s = ln(DEM)`을 구합니다. 최종 답은 `exp(s)` 이고, **exp는 항상 양수**이므로 음수 DEM 사고가 원천 차단됩니다.

대가: `exp` 때문에 방정식이 비선형이 되어 **반복**이 필요해집니다.

### ② 기울기에 벌점을 준다 (도함수 정규화)

DEM의 **크기**가 아니라 **온도에 따른 변화율**에 벌점을 매깁니다. "이웃한 온도끼리 DEM이 급격히 달라지지 마라"는 뜻이고, 물리적으로 타당한 사전지식입니다. 손잡이는 `drv_con = 8`.

### ③ χ²를 최소화하지 않고 χ² = 1을 겨냥한다

χ²가 1보다 작아지면 **부호를 뒤집어 되돌아갑니다.** χ² < 1은 "잡음까지 맞춰버렸다"는 뜻이고, 그렇게 나온 DEM은 진동하는 가짜이기 때문입니다.

| χ² 값 | 의미 |
|---|---|
| χ² ≫ 1 | 잔차가 잡음보다 큼 → 아직 데이터를 못 맞춤 (underfit) |
| χ² = 1 | 잔차가 딱 잡음 수준 → 맞출 수 있는 만큼 다 맞췄다 |
| χ² ≪ 1 | 잡음보다도 잘 맞음 → 잡음을 신호로 착각 (overfit) |

이것이 이 solver의 핵심 특징입니다. 별도로 정규화 세기 λ를 탐색하지 않고, 반복 방향과
step size를 조절해 목표 χ²에 도달합니다.

## 3. 코드 흐름

### 입출력 34–35

```
function simple_reg_dem, data, errors, exptimes, logt, tresps, chi2, $
        kmax=kmax, kcon=kcon, steps=steps, drv_con=drv_con, chi2_th=chi2_th, tol=tol
```

| 이름 | 크기 | 내용 |
|---|---|---|
| data | (nx, ny, 6) | 관측 이미지. 픽셀마다 채널 6개 밝기 |
| errors | (nx, ny, 6) | 각 값의 오차 |
| exptimes | (6) | 채널별 노출시간 |
| logt | (41) | 온도격자 |
| tresps | (41, 6) | 온도응답. 온도 T의 플라즈마가 채널 c에 얼마나 밝게 보이나 |
| chi2 | (nx, ny) | 출력. 픽셀마다 얼마나 잘 맞았나 |
| 반환값 | (nx, ny, 41) | 출력. 픽셀마다 온도별 DEM |

**한 줄 요약:** 픽셀마다 숫자 6개(관측)를 받아 숫자 41개(DEM)를 내놓습니다.

### 기본값 37–42

```
if(n_elements(kmax) ne 1) then kmax = 100
...
```

`n_elements(x) ne 1`은 "인자가 안 들어왔으면"이라는 뜻입니다.

```
kmax    = 100        반복 최대 100번
kcon    = 5          최소 5번은 돌려라
steps   = [0.1, 0.5] 한 번에 움직이는 보폭 후보 2개
drv_con = 8          매끄러움 조절 손잡이
chi2_th = 1          목표 χ²
tol     = 0.1        "충분히 가까움" 기준
```

### 준비 단계 44–54

### — 픽셀과 무관, 딱 한 번

**크기 세기** `44–46`

```
nt = n_elements(logt)        ; 41
nx = n_elements(data[*,0,0]) ; data의 1번축 길이
ny = n_elements(data[0,*,0]) ; data의 2번축 길이
```

`data[*,0,0]`은 "1번축 전부, 나머지는 0번째"입니다. 길이를 세면 `nx`가 나옵니다.

**격자 간격** `47`

```
dT = logt[1:nt-1] - logt[0:nt-2]
logt  = [5.50, 5.55, 5.60, ..., 7.50]     41개
뒤쪽    [5.55, 5.60, ..., 7.50]           40개
앞쪽  − [5.50, 5.55, ..., 7.45]           40개
dT    = [0.05, 0.05, ..., 0.05]           40개
```

이웃한 온도끼리 뺀 것입니다. 여기서는 전부 0.05.

**Bij — 적분 가중치표 (41×41)** `48–49`

```
Bij = (diag_matrix([0,dT]+[dT,0])*2.0 + shift(diag_matrix([0,dT]),-1) + $
       shift(diag_matrix([dT,0]),1))/6.0
```

**하는 일.** 우리가 아는 건 격자점 41개 위의 DEM 값뿐인데, 실제로 필요한 건 적분입니다:

```
채널 c의 밝기 = ∫ (응답) × (DEM) dT
```

격자점 **사이는 직선으로 이었다**고 보고 이 적분을 정확히 계산하면, 각 격자점에 곱해줄 가중치가 나옵니다. 그 표가 `Bij` 입니다. 간격이 전부 0.05이므로:

```
대각선 = (0.05 + 0.05)/3 = 0.0333
옆줄   = 0.05/6          = 0.00833
```

"적분을 행렬 곱셈으로 바꿔주는 표" 정도로 이해하면 충분합니다.

**Rij — 핵심 행렬(6×41)** `50`

```
Rij = transpose(tresps*((1+dblarr(nt))#exptimes)) # Bij
```

안쪽부터 읽으면:

```
(1+dblarr(nt))       → 1이 41개
       # exptimes    → 41×6 표. 모든 줄이 exptimes 복사본
tresps * 그것        → 응답에 노출시간 곱함 (밝기를 DN 단위로)
transpose(...)       → 6×41로 뒤집기
       # Bij         → 적분 가중치 반영
```

**Rij[c, j]의 뜻:** "온도격자 `j`에 DEM이 1만큼 있으면, 채널 `c`가 몇 DN을 받나"

즉 DEM 41개를 관측 6개로 변환하는 행렬이며, inversion에서는 이 관계로부터 DEM을 구합니다.

**Dij — 울퉁불퉁함 벌점표 (41×41)** `51–52`

```
Dij = diag_matrix([0,1/dT]+[1/dT,0]) - shift(diag_matrix([0,1/dT]),-1) - $
      shift(diag_matrix([1/dT,0]),1)
```

간격이 전부 0.05이므로 `1/dT = 20`. 만들어지는 행렬은:

```
[  20  −20    0    0  ... ]
[ −20   40  −20    0  ... ]
[   0  −20   40  −20  ... ]
[   0    0  −20   40  ... ]
```

**하는 일.** DEM이 온도에 따라 톱니처럼 튀면 벌점을 주는 용도입니다.

**각 줄의 합이 0**인 것이 포인트인데, 이는 "DEM이 전체적으로 크든 작든 상관 안 하고, **들쭉날쭉한 것만** 벌준 다"는 뜻입니다.

**벌점 세기 조절** `53`

```
regmat = Dij * n_elements(exptimes) / (drv_con^2 * (logt[nt-1]-logt[0]))
       = Dij * 6 / (8² × 2.0)
       = Dij * 0.0469
```

`drv_con`이 분모의 제곱에 있으므로 **크게 하면 벌점이 약해지고, 작게 하면 강해집니다.**

**rvec — 초기값용 준비물 (6개)** `54`

```
rvec = total(Rij, 2)
```

`Rij`의 41개 온도를 채널별로 전부 더합니다. 뜻은 "모든 온도에 DEM이 1씩 균일하게 있으면, 채널 `c`가 총 몇 DN을 받나".

### 픽셀 루프 56–83

**결과 담을 그릇** `56–57`

```
dems = fltarr(nx,ny,nt)      ; 0으로 채운 빈 배열
chi2 = fltarr(nx,ny) - 1.    ; -1로 채움
```

`chi2`를 **−1로 시작**하는 것이 중요합니다. 나중에 계산이 실패한 픽셀은 −1인 채로 남아 **"이 픽셀은 실패"** 표시가 됩니다.

**픽셀마다 반복** `58–59`

```
for i=0,nx-1 do begin
  for j=0,ny-1 do begin
```

**픽셀끼리는 완전히 독립**입니다. 옆 픽셀 값을 전혀 보지 않습니다.

**이 픽셀의 데이터 꺼내기** `60–61`

```
err  = reform(errors[i,j,*])      ; 오차 6개
dat0 = reform(data[i,j,*]) > 0.0  ; 관측 6개, 음수는 0으로
```

> **IDL 문법 주의 1.** `>`는 비교가 아니라 둘 중 큰 값을 고르는 연산입니다. `a > 0.0`은
> `a`와 0 중 큰 값, 즉 NumPy의 `np.maximum(a, 0.0)`에 해당합니다.

**출발점 정하기** `62`

```
s = alog( total(rvec*((dat0 > 1.0e-2)/err^2)) / total((rvec/err)^2) / (1+dblarr(nt)) )
```

복잡해 보이지만 하는 일은 단순합니다.

**"DEM이 모든 온도에서 똑같은 값 A라고 치고, 데이터에 제일 잘 맞는 A를 구한다."**

앞의 분수가 그 `A` 이고(오차로 가중한 최소제곱 답), `/(1+dblarr(nt))`는 그 값을 **41개로 복사**하는 IDL식 트릭입니다. `alog`는 자연로그.

```
결과 s = [ln A, ln A, ln A, ..., ln A]      41개 전부 같은 값
```

해를 `s = log(DEM)`로 두고 최종적으로 `exp(s)`를 계산하므로 DEM의 positivity가 보장됩니다.

`dat0 > 1.0e-2`는 데이터가 0일 때 `log(0)`이 되는 것을 막는 안전장치입니다.

**반복 시작** `63`

```
for k=0,kmax-1 do begin
```

이제 이 출발점 `s`를 조금씩 고쳐가며 데이터에 맞춥니다.

**풀 방정식 세우기** `64–66`

```
dat  = (dat0 - Rij#((1-s)*exp(s))) / err
mmat = Rij * ((1.0/err)#exp(s))
amat = transpose(mmat)#mmat + regmat
```

> **IDL 문법 주의 2.** `#`은 **행렬 곱셈**입니다.

여기서 벌어지는 일: 우리가 풀고 싶은 관계는 `관측 = Rij × exp(s)` 인데, `exp` 때문에 바로 못 풉니다. 그래서 **지금** `s` **근처에서** `exp` **를 직선으로 근사**해 1차 방정식으로 만듭니다.

`mmat` — 그 직선 근사의 기울기표 (6×41)

`dat` — 우변 (6개)

`amat` — 최종적으로 풀 41×41 행렬. **여기에** `regmat` **이 더해집니다** ← 벌점이 실제로 작용하는 지점

**풀 수 있는지 확인** `67–68`

```
la_choldc, amat, status=stat
if(stat eq 0) then begin
```

`la_choldc`는 41×41 방정식을 빠르게 풀기 위한 사전 분해(Cholesky)입니다. `stat=0` 이면 성공, 아니면 실패.

**지금 얼마나 맞나** `69`

```
c2p = mean((dat0 - Rij#(exp(s)))^2.0 / err^2)
  (관측 − 예측)² / 오차²  를 6채널 평균
```

**"평균적으로 오차의 몇 배만큼 틀렸나"**의 제곱입니다. 1이면 딱 오차 수준.

**어디로 갈지 계산** `70`

```
deltas = la_cholsol(amat, transpose(mmat)#dat) - s
```

`la_cholsol`이 방정식을 풀어 **새** `s` **후보**를 줍니다. 거기서 현재 `s`를 빼면 **이동 방향과 거리**가 나옵니다.

**너무 크게 움직이지 않기** `71`

```
deltas *= (max(abs(deltas)) < 0.5/steps[0]) / max(abs(deltas))
```

> **IDL 문법 주의 3.** `<`는 둘 중 작은 값을 고르는 연산이며 NumPy의 `np.minimum`에 해당합니다.

`0.5/0.1 = 5`. 즉 **이동량이 5를 넘으면 5로 줄입니다**(방향은 유지, 크기만 축소). 한 번에 너무 멀리 뛰면 직선 근사가 깨지기 때문입니다.

**방향 부호 — 이 코드의 특징** `72`

```
ds = 1 - 2*(c2p lt chi2_th)
c2p ≥ 1  (아직 잘 못 맞음)  →  괄호=0  →  ds = +1   앞으로
c2p < 1  (너무 잘 맞음)     →  괄호=1  →  ds = −1   뒤로!
```

**χ²가 1보다 작으면 되돌아갑니다.** χ² < 1은 "잡음까지 맞춰버렸다"는 뜻이고, 그런 DEM은 톱니처럼 튀는 가짜입니다. 그래서 일부러 후퇴시킵니다.

**얼마나 갈지 정하기** `73–76`

```
c20 = mean((dat0 - Rij#(exp(s+deltas*ds*steps[0])))^2.0/err^2)   ; 0.1만큼 가보면?
c21 = mean((dat0 - Rij#(exp(s+deltas*ds*steps[1])))^2.0/err^2)   ; 0.5만큼 가보면?
interp_step = ((steps[0]*(c21-chi2_th) + steps[1]*(chi2_th-c20)) / (c21-c20))
s += deltas*ds*((interp_step > steps[0]) < steps[1])
```

1. 보폭 **0.1**로 가보면 χ²가 얼마가 되는지 계산 ( `c20` )

2. 보폭 **0.5**로 가보면 얼마인지 계산 ( `c21` )

3. 두 점을 직선으로 이어 **χ²가 정확히 1이 되는 보폭**을 추정 ( `interp_step` )

4. 그 값을 **0.1~0.5 사이로 자르고** 실제로 이동

마지막 줄의 `> steps[0]`, `< steps[1]`이 또 max/min입니다 — "0.1보다 작으면 0.1로, 0.5보다 크면 0.5로".

**결과 기록** `77`

```
chi2[i,j] = mean((dat0 - Rij#(exp(s)))^2.0/err^2)
```

움직인 뒤의 χ²를 저장합니다.

```
endif else break
```

67줄에서 분해가 실패했으면 **반복을 중단**하고 직전 `s`를 그대로 씁니다.

**그만할 때** `79`

```
if((ds*(c2p-c20)/steps[0] lt tol)*(k gt kcon) or abs(chi2[i,j]-chi2_th) lt tol) then break
```

둘 중 하나면 종료:

**더 나아지지 않음** — 개선폭이 `tol=0.1` 보다 작고, 최소 `kcon=5` 번은 돌았을 때

**목표 달성** — `|χ² − 1| < 0.1`

( `*`가 IDL에서 `and` 역할을 합니다.)

**답 저장** `81`

```
dems[i,j,*] = exp(s)
```

로그를 벗겨 실제 DEM으로 되돌려 저장하고, 다음 픽셀로 넘어갑니다.

## 4. 개념 보충 — 왜 그렇게 되는가

### 4.1 벌점 함수 P — regmat의 정체

코드에는 `regmat`만 있고 `P` 라는 것은 없습니다. 하지만 `regmat`의 숫자들은 다음 함수를 미분해서 나온 것입니다:

```
P(s) = Σ_j (s_{j+1} − s_j)² / h_j          (h = 격자 간격)
```

**이웃한 격자점 사이의 차이를 제곱해 전부 더한 값**, 즉 "이 `s`가 얼마나 울퉁불퉁한가"를 숫자 하나로 요약한 것입니다.

| s | 모양 | P |
|---|---|---|
| (1, 1, 1, 1, 1) | 완전히 평평 | 0 |
| (1, 2, 3, 4, 5) | 완만한 기울기 | 4 |
| (1, −1, 1, −1, 1) | 지그재그 | 16 |

크기는 셋 다 비슷한데 벌점은 0: 4: 16입니다. **값이 클수록이 아니라 진동할수록** 커집니다.

**미분하면 regmat이 나온다**

`s_k`가 `P`에 등장하는 항은 딱 두 개입니다:

```
… + (s_k − s_{k−1})²/h_{k−1} + (s_{k+1} − s_k)²/h_k + …
∂P/∂s_k = 2 [ −(1/h_{k−1})·s_{k−1} + (1/h_{k−1} + 1/h_k)·s_k − (1/h_k)·s_{k+1} ]
               └── 계수 ──┘        └────── 계수 ──────┘      └── 계수 ──┘
```

이 **계수 세 개를 그대로 행렬의 k번째 줄에** 적은 것이 `Dij` 입니다.

여기서 두 성질이 **저절로** 따라옵니다.

**3줄만 0이 아닌 이유** — `s_k`가 두 항에만 등장하므로 미분 결과에 `s_{k−1}, s_k, s_{k+1}` 세 개만 나옵니다. 이런 모양을 **tridiagonal**(대각선 3줄)이라 부릅니다.

**줄 합이 0인 이유** — `−1/h_{k−1} + (1/h_{k−1} + 1/h_k) − 1/h_k = 0`. 원래 `P`가 **차이**만 재기 때문에, 모든 `s`에 같은 값을 더해도 `P`는 안 변합니다. 즉 **DEM의 전체 크기에는 벌점을 안 매깁니다.**

### 4.2 도함수 정규화란

**정규화** = ill-posed 문제에 "이런 해를 선호한다"는 벌점을 더해 답을 하나로 결정하는 것.

**도함수** = 그 벌점을 해의 **값**이 아니라 **기울기**에 매기겠다는 선택.

| 차수 | 벌점 | 선호하는 해 | 문제점 |
|---|---|---|---|
| 0차 | Σ s_j² | 값이 작은 해 | DEM → 1로 끌어당김. 물리적 근거 없음 |
| 1차 ← 이것 | Σ (s_{j+1}−s_j)²/h | 기울기가 완만한 해 | 전체 크기는 안 건드림 |
| 2차 | 곡률에 벌점 | 직선에 가까운 해 | 더 강한 매끄러움 가정 |

DEM은 온도에 따라 수십 자릿수를 오갑니다. "값이 작아라"는 0차 벌점은 물리적 의미가 없고 해를 임의로 왜곡합니다. 반면 1차는 **"이웃한 온도끼리 급격히 달라지지 마라"** — 타당한 사전지식입니다.

여기서는 `DEM` 자체가 아니라 `s = ln(DEM)`의 기울기에 penalty를 적용합니다. 따라서 DEM의
절대 크기와 관계없이 상대 변화율을 같은 기준으로 제한합니다.

### 4.3 Regularization이 진동 성분을 억제하는 방식

응답함수 `K_c(T)`는 온도에 대해 넓고 매끄럽습니다. DEM에 폭 좁은 지그재그를 얹어 적분하면 `+`와 `−`가 상쇄되어 **6채널 관측값이 거의 안 변합니다.** 반대로 넓고 완만한 변화는 관측을 크게 바꿉니다.

| s의 성분 | 데이터 발언력 | 벌점 | 결과 |
|---|---|---|---|
| 넓고 완만 | 크다 | 작다 (0에 가까움) | 데이터가 결정 |
| 좁고 진동 | ≈ 0 | 크다 | regularization이 억제 |

`regmat`은 관측으로 제한하기 어려운 좁은 진동 성분에 큰 penalty를 주고, 관측에 민감한 넓은
성분에는 상대적으로 작은 penalty를 줍니다.

1변수로 보면 명확합니다:

```
δ = a·b / (a² + λ)
a가 크면 (관측이 민감)   → λ는 무시할 수준       → 데이터 값 그대로
a ≈ 0이면 (관측이 무감각) → λ가 없으면 해가 불안정 → λ가 있으면 ≈ 0
```

두 번째 경우가 regularization 없이 해가 불안정해지는 성분에 해당합니다.

### 4.4 Gauss-Newton — 64~70줄이 하는 일

최소화 대상은 `χ² + (스케일)·P` 입니다. 미분해서 0으로 놓아야 하는데 `exp` 때문에 손으로 못 풉니다. 그래서 접선 근사 `f(x+h) ≈ f(x) + f′(x)h`를 씁니다. `exp′ = exp` 이므로:

```
exp(s_j + δ_j) ≈ exp(s_j) + exp(s_j)·δ_j
```

따라서 `δ_j` 앞에 붙는 계수는 `R[c,j] · exp(s_j) / σ_c` 이고, 이 숫자표가 `mmat` 입니다.

| 코드 | 1변수 대응 | 뜻 |
|---|---|---|
| mmat | a | s가 변할 때 모델이 변하는 비율 |
| transpose(mmat)#mmat | a² | 미분해서 0으로 놓았을 때 미지수 앞 계수 |
| transpose(mmat)#dat | a·b | 우변 |
| + regmat | + λ | 매끄러움 벌점이 계수에 더해짐 |
| Cholesky | 나눗셈 δ = ab/(a²+λ) | 연립방정식 풀기 |

1변수로 보면 `χ² = (a·δ − b)²`를 미분해 0으로 놓으면 `a²·δ = a·b`가 나오고, 벌점을 더한 `(a·δ − b)² +` `λδ²`는 `(a² + λ)·δ = a·b`가 됩니다. 미지수가 41개가 되면 `a`가 행렬 `mmat`이 되고, `a²` 자리에 `mmatᵀ·mmat`이 오는 것뿐입니다.

**어느 행렬에 DEM이 들어있나**

|  | DEM 들어있나 | 언제 계산 |
|---|---|---|
| regmat | 없음. 온도격자만 | 루프 밖, 1회 (53줄) |
| mmatᵀ·mmat | 있음. exp(s_j) 가 곱해져 있 음 | 픽셀마다 · 반복마다 (65–66줄) |
| s | 이것 자체가 log DEM | 우리가 구하는 답 |

### 4.5 Cholesky를 쓰는 이유

`amat`은 41×41 **대칭**이고 제곱합 구조라 **positive definite**입니다. 이런 행렬은 `amat = L·Lᵀ`(L은 하삼각)로 쪼갤 수 있고, 삼각행렬은 위/아래에서 차례로 대입하면 **단순 나눗셈의 연쇄**로 풀립니다.

대칭성을 활용해 연산량이 일반 역행렬의 절반이고 수치적으로 안정

픽셀마다 푸는 행렬이 41×41로 작아 **42.6만 픽셀의 전체 태양 원반 자료도 처리할 수 있습니다.** 이것이 이 방법이 빠른 주된 이유입니다.

`status ≠ 0`은 positive definite가 아니라는 뜻 → 그 픽셀은 반복 중단, `chi2`가 −1로 남을 수 있음 → **마스킹 필요**

### 허용한 차이 2건 — 왜 완전 일치가 아니었나

중간 스칼라 `c20`과 `interp_step`에서 `max_abs 7.2e-8` 수준의 차이가 남았습니다.

원인은 **catastrophic cancellation**입니다. 수렴 근처에서는 `관측 − 예측`이 거의 0인데, IDL의 LAPACK과 numpy의 **부동소수점 누적 순서 차이**(1e-16급)가 이 지점에서 상대오차로 증폭됩니다. 입력( `s`, `deltas` )도 최종 출력( `dems`, `chi2` )도 기준을 통과하므로 인증 출력에는 영향이 없어, 근거를 붙여 승인 처리했습니다.
